## Auth (social only)

**Host trust / scammer protection (mig **522** to **529**):**

Human overview (plain steps): `docs/guides/Dama_Host_Trust_And_Scammer_Protection_Guide.md`.

Plain summary: free cups stay open to anyone. Paid create needs a verified phone, open-cup limits (new host 1 / phone 3 / ID 25), and a clean reputation. Guaranteed prize cups also need verified government ID and real wallet money locked at create (with the host fee); cancel before start unlocks it; start commits it to the pot; finish pays winners after the dispute window. Badges: Unverified host / Phone verified / Verified host.

Goal: money locks remain the payout safety net; identity and caps limit create risk for every organizer cup (not one organizer only).

Layers:
1. **Identity.** Free cups stay light. Paid create requires phone KYC when `cash_rmg_policy.host_paid_create_requires_phone_kyc` (default true). Prize-guarantee create (and guarantee re-hold on reopen) requires approved document KYC when `host_guarantee_requires_document_kyc` (default true). Feature flag `kyc_auto_approve` (default ON; GraphQL `featureFlags.kycAutoApprove` + `consoleFeatureFlags.kycAutoApprove`; REST `/feature-flags` + WS snapshot; Events admin + Feature Flags catalog) auto-approves document KYC on submit; when OFF, admin `/payments/kyc` manual review is required.
2. **Caps and reputation.** Concurrent open paid-cup caps: document-verified hosts use `host_concurrent_open_paid_cap_document_verified` (default 25) immediately; phone-only hosts use `host_concurrent_open_paid_cap_new_host` (default 1) until `host_new_host_settled_paid_threshold` finished paid cups, then `host_concurrent_open_paid_cap_phone_verified` (default 3). Reputation gates: `host_reputation_max_open_reports` (default 5; 0 disables), cancel-rate `host_reputation_cancel_rate_bps` (default 7000) with `host_reputation_cancel_rate_min_sample` (default 5; 0 disables rate gate). Console `GET /console/cash-rmg/policy` returns live fields; admin Sales → **Host trust policy** (`/payments/host-trust`, mig **532**) edits them via `PUT /console/cash-rmg/host-trust-policy` (`feature_flags.write`; OpsDataTable tabs Gates / Caps / Reputation).
3. **Escrow.** Guarantee hold at create (with host fee in one TX), release before start, capture at start, finish via competition escrow + dispute + settle (mig **508** hardening). Layer D also includes prize auto-settle, cancel/refund before live, and report + deactivate.

Badges and stamps: Public / mine / joined / console event payloads stamp `organizer_host_trust_tier` + `organizer_host_trust_badge` plus reputation counts (`organizer_finished_paid_cups`, `organizer_cancelled_paid_cups`, `organizer_open_reports`) via `attachOrganizerCard` (lists) or `publicEventWithHost` (single-event responses). ## Core mandates



1. Zero hardcoding in Flutter / Next.js: hydrate from the database via Go APIs.

2. FMJD 10x10 rules: mandatory capture, majority capture, flying kings.

3. VS-AI is console-toggled and 100% non-monetary.

4. Games default to paid; console `is_free` override bypasses entry fees. Free cups use Join (silent enroll, no payment modal) then open the cup lobby (`/?view=tournaments&id=` / Flutter lobby sheet); paid cups use Enroll + wallet modal then the same lobby. Already-enrolled (HTTP 409) maps to `payment_modal_chrome.already_enrolled` on all clients.

5. Tournament and hosted-event lists are DB skip/limit paginated with server-side filters (`is_free` / `is_free_entry`, `q`, and status on organizer/console). Never page a client-only slice of an unfiltered dump.

6. Geo payment routing: Ethiopia to local checkout or manual transfer; elsewhere to international checkout. Currencies come from platform settings (global vs Ethiopia).

7. **Wallet top-up E2E (player / organizer / publisher money shells):** `POST /payments/checkout` resolves the provider from **server geo only** (loopback/private invents domestic country from `platform_settings.geo_payment` - so local dev is usually Ethiopia/`manual_transfer`, never Paddle).  
   - **`manual_transfer`:** intent `status=awaiting_receipt`, `checkout_url` empty, `banks` attached. Clients **must** show banks + receipt UI immediately. Web keeps `formKind=topup` and flips `topupStep` to `manual_instructions` (Smart Menu step pattern - avoids Radix dismiss on formKind remount). Flutter opens `_openReceiptSheet` after the top-up sheet closes. Deep link `?focus=receipt` (also `?focus=topup` / `?focus=payout`) opens that form on wallet load. Toast-only / close-dialog-only is a product bug. Player then uploads proof → admin reviews → wallet credit.  
   - **Sticky Cancel / Submit (Smart Menu parity, mig **337**):** web/admin `DialogContent` flattens fragments then extracts `damaDialogFooter` / `DialogFooter` outside the scroll body (plus Smart Menu `sticky bottom-0` safety net); wallet payment footers are direct `DialogContent` children (not nested in `<>`); Flutter receipt sheet keeps Cancel + Submit in a non-scrolling bottom bar. Gold-tinted footer chrome on payment/banks dialogs.  
   - **Bank copy (Smart Menu parity, mig **337**):** web `ManualBankAccounts` + admin banks detail `CopyableDetailRow` + Flutter `_bankCopyRow` expose copy icons for account name / number / mobile with `wallet_chrome` / `admin_console_chrome.banks` labels (`copy_action`, `toast_copied`, `toast_copy_failed`, `bank_copy_*` / `copy_*_label`).  
   - **Branded receipt modal:** gold border + header wash + gold-accent bank cards on web/admin; Flutter bank cards use `DamaColors.gold` gradient borders. Shared across player / ads / events wallet shells (`WalletWorkspace`).  
   - **`local_checkout` (Chapa) / `international_checkout` (Paddle):** non-empty `checkout_url`; clients same-tab `location.assign` / external launch (not popup-blocked `window.open`).  
   - Bank `account_number` / `mobile_code` are AES-GCM sealed with **`DAMA_SECRETS_KEY`**. After a key rotate, re-save accounts in admin Payments → Banks; sealed ciphertext must never be shown to players.
