QUICK MAP (what to use for what)
--------------------------------------------------------------------------------

  storePassword           = unlocks the .jks file
  keyPassword             = unlocks the "upload" key inside the .jks
  keyAlias "upload"       = name of the key inside the .jks
  key.properties          = tells Gradle where the keystore is + passwords
  app-release.aab         = the file you upload to Play Console
  mapping.txt             = optional; helps Play decode crash stack traces
  SHA1 / SHA256           = prove to Play / support which upload cert you own

3) key.properties (Gradle signing config)
================================================================================
  WHAT IT IS
    Small text file that connects the Flutter/Android release build to your
    upload keystore. Without it, a "release" AAB may be debug-signed and
    Play will reject it.

  PATH
    apps\mobile\android\key.properties
  TEMPLATE (safe to commit; no real passwords):
    apps\mobile\android\key.properties.example

  WHEN
    - First time on a machine before any Play AAB build
    - After you restore the .jks onto a new PC
    - If release builds suddenly become "wrong key" / unsigned

  WHERE
    Same folder as upload-keystore.jks:
      apps\mobile\android\

  HOW
    1. Copy key.properties.example to key.properties
    2. Fill the four lines using section 2 above
    3. Confirm storeFile=upload-keystore.jks (relative to android/)
    4. Build (section 4)

5) mapping.txt (R8 / ProGuard deobfuscation)
================================================================================
  WHAT IT IS
    Map file so Play Console can show readable crash stack traces for
    minified release builds.

  PATH
    apps\mobile\build\app\outputs\mapping\release\mapping.txt

  WHEN
    - After each release AAB you upload (recommended)
    - When Play Console asks for a deobfuscation / mapping file
    - When investigating production crashes that look obfuscated

  WHERE
    Play Console -> your app -> Release / App bundle explorer /
    or the crash / ANR deobfuscation upload field for that version

  HOW
    1. Build the AAB (section 4) so mapping.txt is regenerated
    2. Upload the mapping.txt that matches THAT same AAB version
    3. Do not reuse an old mapping.txt for a newer build
