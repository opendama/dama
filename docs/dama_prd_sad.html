dama Tournament & Gaming Platform

Product Requirements & Technical Architecture Document (PRD & SAD). Print-ready companion to docs/prd-compliance.md.

1. Architecture

Hybrid client API: GraphQL (primary), REST (webhooks, uploads, invoices, enroll, progression, invites), raw Go WebSockets (live board, matchmaking, invites, spectate, feature flag push). Zero client hardcodes. PostgreSQL via Supabase, Redis, Cloudinary, Paddle/Chapa.

3. Core product rules

  • Auth is Google social only (Supabase OAuth PKCE → POST /api/v1/auth/oauth/supabase → dama JWT). No email/password register or login. Auth chrome (titles, nav_sign_in_label, sign_out_action_label, paths, OAuth params, errors, login_success_message, admin_login_*) is database-only via platform_settings.auth_providers / GET /public/auth-providers; clients fail closed with no path or copy hardcodes. Edge middleware forwards stray ?code= to the callback; callbacks require every linked IdP identity on the allow-list; callbacks and exchange enforce email_domain_denylist (seeded disposables) for brand-new OAuth identities.
  • Player payouts require a primary phone (length ≥ 8) on bank/mobile-money details (PUT /payouts/method) and, when require_document_kyc_for_payout, an admin-approved government-ID document KYC (ID front/back + selfie + legal name + document type via /kyc/documents/*; migrations 067–072 + 293 dropped printed ID metadata fields) before POST /payouts/request (wallet debit + pending request) on web and Flutter wallet. Wallet/payout UI chrome is database-only via platform_settings.wallet_chrome / GET /public/wallet-chrome (API + clients fail closed when incomplete). Console operators approve/reject/mark-paid via /payouts/console and Identity KYC via /kyc/documents/console using DB cash_rmg_policy statuses (reject refunds wallet).
  • Shared Telegram ops bot for manual receipt + payout (migrations 415–425): Dama API fail-open notifies the shared worker (dama_receipt_pending / dama_payout_pending, never legacy manual_payment_claim); bot routes to DAMA_API_BASE_URL with X-Bot-Key on /telegram-bot/admin/dama/…; receipt 1-step / payout approve→paid; console remains SoT at /payments/telegram-ops; web/Flutter unchanged (server notify on submit). Details: docs/architecture.md, docs/prd-compliance.md.
  • Cash / RMG store compliance (migrations 062–072 + 293): fail-closed EvaluateCash on paid enroll, checkout, manual receipt, and payout. DB cash_rmg_policy / cash_rmg_chrome; flags cash_rmg_enabled (+ disabled_countries) and cash_phone_kyc_required (REST + GraphQL); admin CRUD for allowlist allowed_country_codes via /console/cash-rmg/allowed-countries (Feature Flags console); Phase C document KYC (kyc_document_submissions: gov ID front/back + selfie + legal name + document type; admin image review + history filter; MediaDropzone; migrations 067–072 + 293); web/Flutter paid-enroll UI hides when kill switch or country disable list blocks cash; 18+ age gate; jurisdiction allowlist; fresh geo_ip_records locate; phone-channel OTP KYC (not email). Legal cash 18+ sections retain under-13 COPPA language. Native packaging notes: apps/mobile/STORE_PACKAGING.md.
  • FMJD 10x10 International Draughts with mandatory/majority capture and flying kings.
  • Admin VS-AI practice (non-monetary), DB-backed depths with console CRUD, runtime feature flag + WSS push.
  • FMJD board_rules in platform_settings (size, pieces, setup rows, variant) via /api/v1/game/rules; web board hydrates size from live game state.
  • Admin game/tournament is_free override: zero entry fee, wallet bypass, stats retained.
  • Prize pool display (mig 267): paid cups only show DB-backed prize_pool_now / prize_pool_if_full (+ optional organizer guarantee hold). Admin flags + organizer create toggle; free forced off; Start freezes then MarkLive then captures hold (capture fail reverts live and clears freeze; no sticky freeze); cancel before start releases hold; platform kill-switch omits pot JSON; host fee never in pot; if_full only when max seats ≥ 2; guaranteed card line requires hold. Tournament live pot is enrolls × entry fee (+ declared prize_pool.total guarantee); omit pot on enroll-count error; freeze when leaving enrollable (fail closed if entries unavailable).
  • YouTube media pool console accepts OAuth2 + API key vault fields (AES at rest); avatar moderation rules console CRUD.
  • Live match HUD places seat avatars beside match clock, captured counters, level badges, and country codes from backend payloads.
  • Ad geo Redis index is country/region/district scoped (no silent GLOBAL leak) plus Redis GEO radius matching when campaigns include lat/lng/radius_km.
  • Player portals (web + mobile) call /ads/serve; server resolves match geo from IP/GPS (client country query ignored). Clients record impression, unique reach (viewer_key), click, and video-complete telemetry.
  • Player inspect modal includes recent matches and tournament placement history from the public player API.
  • Publisher analytics shows impressions, unique reach, CTR, CPC, and video completion rate with PDF invoice export.
  • Publisher campaign create UI accepts district, lat/lng, and radius_km for hyper-local fences.
  • Admin user soft activate/deactivate via PATCH /console/users/{id}/active (no hard DELETE); disabled accounts cannot mint sessions, and Redis disable gate rejects existing JWTs instantly.
  • Client theme follows OS preference by default (system), with an explicit system/light/dark cycle toggle on web, admin, and Flutter; surfaces and chrome use CSS / DamaColors tokens (no hardcoded light-only or dark-only UI).
  • YouTube vault admin Test readiness endpoint POST /media/pool/channels/{id}/test runs preflight against the selected channel.
  • GraphQL AdCampaign.uniqueReach / videoCompletions and PublisherDashboard.totalUniqueReach hydrate publisher analytics.
  • Matchmaking and seat cards show regional flags derived algorithmically from ISO country codes (no hardcoded country tables).
  • VS-AI Grandmaster depth ceiling is Depth-10 (DB allow-list authoritative; no invent remap to 12).
  • Web profile loads recentMatches via GraphQL; inspect modal supports pinch/wheel zoom on full avatars.
  • Tournament enroll shares the OTP gate with checkout and matchmaking when admin enables OTP.
  • VS-AI search depth is allow-listed only; invalid depths return no move (no silent remap).
  • Tournament soft lifecycle CRUD: draft / open / archived; public list and enroll only when open.
  • Feature flag store fails closed; Ethiopia payment mode must be explicit chapa or manual (no invent).
  • Engine setup uses DB board_rules.setup_rows + variant (size must match FMJD 10).
  • Avatars via Cloudinary (avatar_thumb / avatar_full) with inspect modal, seat presence, and online status dots.
  • Leaderboards show DB level badges and live online indicators (web + mobile).
  • XP ladder + authoritative dual match clock + flag-fall from platform_settings.match_clock (console CRUD + public hydrate; mig 427–431). Server arms both seats on StartGame / queue / invite / tournament / hosted; initial_seconds must ∈ presets; debit+persist on move (seat-before-debit) and GetGameState (already-zero flags); rotating 2s sweeper over clock-active index (PvP+AI); end_reason=clock_flag; WS+REST claim; web+Flutter interpolate only (no cosmetic invent); reconnect never rewinds remaining.
  • Server-authoritative pause/resume (mig 471–474): POST /games/{id}/pause|/resume; freezes dual clocks and blocks moves/flag/AI while paused; match_clock.pause_enabled + pause_duration_seconds admin Progression CRUD (number input + Seconds/Minutes unit); sweeper auto-resume on expiry; same Redis engine.State for VS-AI, PvP, official tournament, and organizer hosted games; web+Flutter board Pause/Resume, leave-board auto-pause, floating Resume FAB with DB pause_remaining_fmt countdown.
  • Currency: global USD + Ethiopia ETB from DB + geo. Admin console CRUD on /console/currency. No client ETB default.
  • Mobile profile inspect supports pinch-to-zoom on full-resolution avatars.
  • Ad impression unit cost from platform_settings.ad_pricing with admin console CRUD.
  • Matchmaking shows self avatar card; matched seats hydrate for inspect before board open.
  • Direct match invitations: REST create + pending list; WSS invite_accept / invite_decline on web and mobile matchmaking clients.
  • OTP gate on web and mobile when admin enables global OTP (live flag push over WSS).
  • YouTube multi-channel OAuth vault with async failover upload pool and real multipart video body upload.
  • Cloudinary avatar pipeline: thumb 128 and full 1024 delivery URLs from DAMA_MEDIA_PUBLIC_BASE.
  • Geo payments: Ethiopia Chapa or manual transfer; international Paddle. Wallet clients resolve country via GPS then GeoIP (no hardcoded ETB).

4. Security (8-layer in-repo)

  1. Edge WAF / CDN (OPS_EXTERNAL in production)
  2. Redis leaky-bucket rate limiting (Lua)
  3. Go API gateway / CORS
  4. TLS 1.3 (mTLS OPS_EXTERNAL)
  5. JWT + Redis revocation + RBAC
  6. GraphQL depth / complexity + introspection off
  7. Business rules + PostgreSQL RLS
  8. AES-256-GCM vault + append-only audit
  9. Chapa + Paddle webhook HMAC verification (fail closed without secrets)
